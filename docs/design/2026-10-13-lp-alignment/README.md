# LPとアプリの整合・デザイン改善 — 2026-10-13

## ユーザーの依頼
LPとアプリに差異がないか、LPからアプリに取り入れるべき点は何かを確認し、LPデザインを改善する。

## 照合結果と対応
| 従来のLP | 実装上の状態 | 対応 |
|---|---|---|
| 車内モードの画像に路線の進行図・ふりがながある | `index.html`のriding-screenは駅名・状態・距離等。進行図やふりがな欄はない | 作ったモックを外し、実画面を撮影した画像に変更 |
| 「現在駅」がすぐ分かる | `render`はGPSから最寄りを判定。200m以内を「いまここ」と扱う | GPSの推定・最寄り駅表示・地下での限界を明記 |
| 目的地設定・次駅を一般機能のように掲載 | `dest-btn`と`setAlert`はrequirePremiumで制限。`renderNextStation`はPlusと移動方向が必要 | 駅検索・地図を含む目的地機能、次駅予測、履歴等をPlusに分類 |
| 降車前に気づけるという説明 | `checkAlert`は位置更新時、設定駅の600m圏内で発火。常時バックグラウンド通知を保証する仕組みではない | 位置取得・端末・通知設定の条件を明記 |
| Plusの現状を説明していない | config.jsのbackendUrlが空。applyPlanUIは課金を表示せずデモ有効化 | 現時点のデモ・請求なしを説明 |
| 対応範囲の説明がない | 内蔵駅データは首都圏・関西、圏外はOverpass。目的地検索は全国 | FAQで分けて説明 |
| アプリ開始画面「保存しません」 | 正確な座標は運営者へ送らないが、圏外で丸めた座標を外部送信。Plus履歴・設定は端末保存 | 開始文言を「正確な位置情報を運営者に送信・保存しません」に日英修正。LPに詳細 |

## デザイン
- 白に近い背景、濃い青灰色、控えめな真鍮色。既存の写真素材を1点に絞り、実画面を重ねて主役を明確にした。
- 写真の繰り返しと実装にないUIモックをやめ、通常／車内モードを切り替えるプレビュー、ガイド実画面、機能区分、使い方、FAQへ再構成。
- 影・フレーム・写真の重なりで厚みを残す。人物イラストは使わない。
- 新しい画像は実装中の画面のスクリーンショット。新宿の固定テスト座標で撮影し、ユーザーの現在地や履歴は使用しない。掲載画面はサンプルと明示。
- 固定の新宿表示の撮影用ページは公開しない。実アプリのロジックをLP内で動作させず、実画面の静止画として説明する。

## アプリへの取り入れ候補（今回は提案）
1. 初回だけ、車内モードの入り方・戻り方を短く案内。大きい駅名表示の価値に気づきやすくする。
2. ホーム画面への追加案内。PWA対応はあるが、アプリ内の導線はまだない。
3. 次駅の推定・位置精度・更新停止をユーザーが見分けられる表示。路線進行図を追加する場合も、確定した運行情報のように見せない。
新機能の優先順位はこの提案で固定せず、オーナーの判断に委ねる。

## 検証
- Chromeで320px、390px、1280px。狭いヘッダーの折り返しを修正し、横はみ出しなし。
- 通常／車内モードの切り替え、選択状態・非表示制御、FAQの開閉を確認。
- 画像の読み込みとブラウザのエラーログ、JS構文、HTML参照とオフライン素材を確認。
- アプリの計測・通知ロジックは変更しない。列車内の実測試験は行っていない。
- 今後config.jsで実課金へ切り替える際はLPのデモ説明も更新する。
