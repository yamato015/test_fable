## 1. プロダクト概要

**エキココ**は、電車内で「いま自分がどの駅にいるか」を特大表示で確認できるPWA。
混雑した車内で座っていると電光掲示板が見えない——という不便を解決するのが
唯一の目的。乗換案内アプリではない（経路検索・時刻表は非対応）。個人開発・β公開中。

## 2. 絶対に守る制約（変更禁止）

- **車内モード (`#riding-screen` / `.riding`) の背景は必ず黒 (`#000`)**。
  OLED端末での省電力のため。装飾を加えるのは可だが背景色は変えない
- **駅名の特大表示・視認性を落とさない**（`.station-name` のサイズ設計は維持）。
  座った姿勢からのチラ見が最優先要件
- **各要素の `id` を安易に変更しない**。`app.js` が直接 `document.getElementById`
  相当（`$()`ヘルパー）で参照している。`id` を変える場合は `app.js` 側の対応する
  参照も同じコミットで必ず更新すること（grepで `id="xxx"` と `$("xxx")` の両方を確認）
- **絵文字を使わない**。`index.html` の `#icon-sprite`（`<symbol id="i-xxx">`）に
  自前SVGアイコンを定義済み。新規アイコンが必要なら同じ流儀（線幅1.7px、
  `stroke="currentColor"`）で追加し、既存の呼び出し方 `<svg class="ic"><use href="#i-xxx"/></svg>`
  および動的生成用の `app.js` の `icon(name, cls)` ヘルパーを使うこと
- **多言語対応 (i18n) を壊さない**。静的文言は `data-i18n` / `data-i18n-html` /
  `data-i18n-ph` 属性、動的文言は `app.js` の `STRINGS.ja` / `STRINGS.en` と
  `t(key, ...args)`。文言を追加・変更する場合は **`ja` と `en` の両方**を更新すること
- **位置情報は端末内処理**。外部送信は既存のOverpass API呼び出し以外に増やさない
  （新しい外部通信を追加しない）

## 3. 今のデザインの到達点（この方向性を土台に磨くこと）

以前、生成AIっぽい装飾（ぼかしたカラーグロー、斜めグラデーション+同色ハロー影、
発光ドット、リング状パルス、過大な角丸）を実装したところ「AIっぽい」と
指摘され、**実在する鉄道サインの質感**へ全面的に作り直した経緯がある。
**この方向性の否定・後戻りは絶対にしないこと**（ガラス風・浮遊3Dブロブ・
ネオングローのようなあしらいは禁止）。

現在のモチーフ:

- **駅名標**: カードではなく金属板のプレート。上端に路線の公式カラー帯、
  影を段階的に重ねた硬い厚み（`filter: blur()` によるグローは使わない）
- **物理ボタン**: 底面に色を持たせ、押すと沈む（`box-shadow` の階段重ね＋
  `transform: translateY()`）
- **路線タグ**: 実際のJR/私鉄の路線カラーを使用（`app.js` の `lineColor(name)`
  が `window.LINE_META` から公式カラーを返す）
- **車内モード**: 上下を路線カラーの帯で挟む。背景は黒固定
- **降車アラート**: 踏切の警告灯のような機械的な点滅（`steps()` イージング、
  フェードではない）
- **起動画面 (`#start-screen`)**: CSS 3D変形 (`perspective` + `preserve-3d`) で、
  駅名標が線路脇に実際に「立っている」場面。地面を傾けて奥へ収束する線路、
  板の厚みは影の階段重ね、支柱で接地。緩やかな左右の揺れ（11秒周期、
  `prefers-reduced-motion` で停止）
- **アイコン**: 絵文字を全廃し、線幅1.7pxで統一した自前SVGに統一済み
- **モーダル**: 中央ダイアログではなくボトムシート。ヘッダーは `position: sticky`
  で固定（スクロールしても閉じるボタンが常に見える）
- **ライト/ダーク**: `body[data-mode="light"]` で独立して切替可能。アクセントは
  `body[data-theme="amber|blue|pink"]` で3色切替（別軸）

## 4. やってほしいこと（改善の宿題）

「もっと自然で綺麗に」「もっと3Dに」という抽象的な要望が出ている。以下は
現状の弱点の仮説（確定ではない。実際に画面を見て自分で診断し直してよい）:

1. **立体表現が起動画面だけに閉じている** — メイン画面の駅名標・ボタンは
   影の重ねによる疑似立体止まり。起動画面のような実際のCSS 3D変形を、
   ボタン押下・モーダル開閉・路線図タップなど他の要素にも部分的に
   使えないか検討する
2. **モーション同士の一貫性がない** — 起動画面の3D揺れ、ボタンの沈み込み、
   モーダルのスライドイン、ガイド図解のアニメーションがバラバラに実装されて
   いる可能性がある。duration・easingを統一したモーション言語にする
3. **情報密度の高い画面の垢抜け感が弱い** — 目的地検索・路線図・乗り方ガイドの
   一覧が、駅名標やトップページに比べてリストの羅列に見える可能性がある
4. **過剰な主張を削る** — 力の入れどころを絞り、全体として「自然」に見える
   よう調整する

## 6. 実装後にやること（デプロイの前提条件・忘れると反映されない）

1. **`python3 tools/bump_cache.py` を必ず実行する。** `sw.js` の
   `CACHE_NAME` をインクリメントするスクリプト。これを忘れると
   Service Workerが古いキャッシュを配り続け、**ユーザーの端末に変更が
   一切反映されない**（このプロジェクトで実際に何度も踏んだ罠）
2. 静的アセット（`index.html` / `style.css` / `app.js` / アイコン画像等）を
   変更した場合は必ず上記を実行してからコミットすること
3. コミットメッセージは変更内容と検証方法を明記する（このリポジトリの
   既存コミットログ参照）

## 7. 検証方法

自動テストフレームワークは無い。以下を最低限確認すること:

- `node --check app.js` で構文エラーが無いこと
- ブラウザ（可能ならヘッドレスブラウザ/Playwright等）で実際に画面を開き、
  - 横方向のはみ出しが無いこと（`document.documentElement.scrollWidth <=
    document.documentElement.clientWidth`）
  - 起動画面 → 「現在地を確認する」→ メイン画面への遷移が壊れていないこと
  - ライトモード・ダークモード両方で崩れていないこと
  - 車内モードの背景が黒のままであること
  - モーダル（目的地・乗り方ガイド・プレミアム）を開き、スクロールしても
    閉じるボタンが見え続けること
  - 乗り方ガイドのきっぷ種別チップで表示が絞り込まれる機能が壊れていないこと
- JSコンソールにエラーが出ていないこと

## 8. 変えてよいもの / 変えてはいけないもの（まとめ）

**自由に変えてよい**
- モーション設計全体（統一したイージング・duration・3D活用方針）
- 配色の微調整（トークンの値。仕組み自体は維持）
- コンポーネントごとの立体表現の手法
- 情報密度の高い画面のレイアウト・カード設計
- 新しいマイクロインタラクション
- 新しいSVGアイコンの追加（既存の流儀に沿う場合）

**変えてはいけない**
- 「実在する鉄道サインの質感」という大方針（3節を参照）
- 車内モードの黒背景
- 駅名の特大サイズ・視認性
- 各要素の `id`（変更する場合は `app.js` の参照も同時に更新）
- 絵文字への回帰
- i18n（`data-i18n` / `STRINGS.ja` / `STRINGS.en` の両方更新）の欠落
- 新しい外部通信の追加
- `claude/practical-babbage-xrtvmo` 以外のブランチをターゲットにすること
  （`main` へは直接pushしない）
