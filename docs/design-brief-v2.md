# エキココ (EkiKoko) — UI/UXブラッシュアップ v2 要件定義書

> 前回(design-brief.md)のClaudeDesign案を統合・実装済みの状態からの**2周目**の
> ブラッシュアップ依頼です。ゼロから作り直すのではなく、今の方向性を土台に
> 磨き込んでください。この文書は別のClaude会話にそのまま貼り付けて使えます。
> 返ってきた案は、この開発者(Claude Code)側で既存コードに統合します。

## 1. プロダクト概要

**エキココ**は、電車内で「いま自分がどの駅にいるか」を特大表示で確認できるPWA。
混雑した車内で座っていると電光掲示板が見えない——という日常の小さな不便を
解決するのが唯一の目的。乗換案内アプリではない（経路検索・時刻表は非対応）。

- 一人開発・β公開中
- フレームワーク不使用のバニラJS/HTML/CSS、ビルド工程なし
- GitHub Pagesで静的配信

## 2. 使われ方（デザインに直結する制約・不変）

- **利用シーン**: 満員電車・座席・片手・チラ見
- **視認性が最優先**: 座った姿勢から一瞥で駅名がわかる（駅名は特大表示。死守）
- **車内モード**: 画面をずっと点灯させる用途があり、**OLED節電のため背景は必ず黒**
- **ターゲット**: 日本の通勤・通学者がメイン。副次的に訪日外国人（多言語対応あり）

## 3. 現在地: 1周目で何をしたか（v1の要約）

1周目の要件は「見た目・世界観の洗練」。ClaudeDesign案を統合した後、ユーザーから
「AIっぽい」という指摘を受けて以下の方向転換をした。**この転換の結論こそが
v2で守るべき現在の世界観**:

### v1前半 (ClaudeDesign初回案・のち破棄した要素)
- ぼかしたカラーグロー、斜め45度グラデーション+同色ハロー影、発光ドット、
  リング状パルス、過大な角丸(28px)
- → ユーザー評価: 「AIっぽい」。生成AIが作るUIに典型的な"実在しないツヤ"だった

### v1後半 (方向転換後・現在の実装)
**モチーフ:** 鉄道の実在するサインの質感。「個人開発者が作った気の利いた道具」

- **駅名標**: カードではなく金属板のプレート。上端に路線の公式カラー帯、
  影を段階的に重ねた硬い厚み（ぼかし禁止）
- **物理ボタン**: 底面に色を持たせ、押すとその分だけ沈む（トランジションで
  疑似的に立体を再現。CSS box-shadowの階段状の重ねが基本手法）
- **路線タグ**: 実際のJR/私鉄の路線カラーを使用（緑・青・橙など、装飾色ではない）
- **車内モード**: 上下を路線カラーの帯で挟む。背景は黒固定、ぼかしグローは無し
- **降車アラート**: 踏切の警告灯のような機械的な点滅（`steps()`、フェードでない）
- **起動画面**: CSS 3D変形(perspective + preserve-3d)で、駅名標が線路脇に
  実際に「立っている」場面。地面を傾けて奥へ収束する線路、板の厚みは影の
  階段重ね、支柱で接地。緩やかな左右の揺れ(11秒周期)
- **アイコン**: 絵文字を全廃し、線幅1.7pxで統一した自前のSVGアイコンに統一
  (index.html内の`#icon-sprite`。26種・111箇所を置き換え済み)
- **モーダル**: 中央ダイアログではなくボトムシート。ヘッダーはsticky固定
  (スクロールしても閉じるボタンが常に見える)
- **ライト/ダーク**: 独立した軸として両対応。ライトモードは実物の駅名標に
  非常に近い見た目になっている（好評）

### 現在のデザイントークン (`style.css` の `:root` より)

```css

  --fg: #f3efe6;
  --sub: #8d90a0;
  --accent: #ffb020;      /* amber基調。3色切替(amber/blue/pink)の1つ */
  --accent2: #ff6b4a;
  --card: #15161d;
  --card-border: rgba(255, 255, 255, 0.07);
  --line: rgba(255, 255, 255, 0.08);
  --danger: #f85149;
  --on-accent: #151007;
  --plate: #1b1d24;        /* 駅名標の地色 */
  --plate-edge: rgba(255, 255, 255, 0.1);
  --plate-shadow: #05060a; /* 板の厚み用の影色 */
  --btn-edge: #05060a;     /* 物理ボタンの底面色 */
}

body[data-mode="light"] {
  --bg: #f6f2ea; --fg: #181920; --sub: #6d7080;
  --card: #ffffff; --card-border: rgba(20,20,30,.08); --line: rgba(20,20,30,.08);
  --plate: #ffffff; --plate-edge: rgba(20,20,30,.16);
  --plate-shadow: #d3ccbe; --btn-edge: #cfc7b7;
}

body[data-theme="amber"] { --accent: #ffb020; --accent2: #ff6b4a; }
body[data-theme="blue"]  { --accent: #4fc3f7; --accent2: #ffb020; }
body[data-theme="pink"]  { --accent: #ff6fa5; --accent2: #4fc3f7; }
```

- フォント: `"Hiragino Sans","Noto Sans JP","Yu Gothic",sans-serif`（Webフォント不使用）
- 角丸: 6〜14px程度（v1前半の28pxから縮小。案内板らしい締まり）
- 影: ぼかし(`blur()`)は**車内モードの装飾グローだけ**残り、他は全て段階重ねの
  硬い影に置き換え済み

## 4. v2で改善したいこと（ここが今回の宿題）

**「もっと自然で綺麗にしたい」「もっと3Dに」**という抽象的な要望が出ている。
1周目で大枠の方向性（実在する物の質感）は固まったので、v2は**その方向性の中で
精度を上げる**フェーズ。以下は現状の弱点の仮説（確定ではない、ClaudeDesign側で
再評価してよい）:

1. **立体表現が起動画面だけに閉じている** — メイン画面の駅名標・ボタンは
   「影の重ね」による疑似立体止まり。起動画面のような実際のCSS 3D変形
   （perspective/preserve-3d）を他の要素にも部分的に使えないか
   （例: ボタン押下時の回転、モーダルの開閉、路線図のホバー/タップ）
2. **モーション同士の一貫性** — 起動画面の3D、ボタンの沈み込み、モーダルの
   スライドイン、ガイド図解のアニメーションが、それぞれ別々に作られていて
   統一されたモーション言語になっていない可能性がある
3. **情報密度の高い画面 (目的地検索・路線図・ガイド一覧) の垢抜け感** —
   駅名標やトップページほど作り込まれておらず、リストや箱の羅列に見える
   可能性がある
4. **「自然さ」** — 現状はまだ意図的なデザインの主張が強い箇所があるかもしれない
   (路線カラーの帯、影の付け方など)。過剰装飾に振り戻さない範囲で、力の
   入れどころを絞ってよい

## 5. 変えてよいもの / 変えてはいけないもの

**自由に変えてよい**
- モーション設計全体の作り直し（統一したイージング・duration・3D活用方針）
- 配色の微調整（現在のamber基調・3テーマ切替の仕組みは維持、値の調整は可）
- コンポーネントごとの立体表現の手法（box-shadow階段 / 実CSS3D変形の使い分け）
- 情報密度の高い画面（検索・路線図・ガイド）のレイアウト・カード設計
- 新しいマイクロインタラクション

**変えてはいけない（今回のスコープ外・機能要件）**
- 「実在する鉄道サインの質感」という大方針そのもの（ガラス風・浮遊3Dブロブ
  など"AIっぽい"と判定された表現には戻さない）
- 車内モードの**黒背景**（OLED節電）
- 駅名の**特大サイズ・視認性**
- 各要素の`id`（JSが直接参照。変更する場合は対応表を明記）
- アイコンを絵文字に戻さない（自前SVGスプライトの方針を維持）
- ライト/ダーク・3色テーマ切替の**仕組み自体**（トークンの値は変更可）

## 6. 画面インベントリ（現状の実装。スクリーンショット添付済み）

| 画面 | 現状 | v2で特に見てほしい点 |
|---|---|---|
| 起動画面 | 立体の駅名標が線路脇に立つ3D場面 | この完成度を他画面にどう波及させるか |
| メイン画面 | 駅名標(疑似立体)+周辺駅リスト+操作ボタン | リストの単調さ、情報階層 |
| 車内モード | 全画面黒+路線カラー帯+超特大駅名 | このままで良いか、装飾追加の余地 |
| 目的地検索/路線図 | ボトムシート、検索リスト、路線図(縦ライン) | 一番「作り物のリスト」感が強い可能性 |
| 乗り方ガイド | きっぷ種別チップ+アニメーション図解 | 図解とレイアウトの一体感 |
| プレミアム(paywall) | 機能リスト+価格+CTA | コンバージョン画面としての作り込み |

## 7. デザイン受け渡しフォーマット（前回と同様・厳守）

1. **今回の変更方針の要約**（2〜3文。何を・なぜ変えるか）
2. **更新後の `:root` トークン**（変更点のみで可。フルセット再掲でも可）
3. **主要コンポーネントのHTML/CSSスニペット**（変更する箇所のみ）
   - 特に見てほしい: メイン画面の駅名標、ボタンのプレス演出、モーダルの
     開閉モーション、目的地検索リストの見せ方
4. 既存の`id`を変更する場合は**旧→新の対応表**を明記
5. モーション変更がある場合は、`transition`/`animation`の**duration・easing**を
   明記（実装側で統一言語として揃えるため）

テキストのみの会話でも、CSS/HTMLコードとして返してもらえれば十分です。
