## 1. オーナーの指摘（2026-10-19）
1. 更新のタイミングが課題。自動なら仕組みを見直す。手動の更新ボタンを置くのもあり
2. 乗っている路線の決定が遅く、曖昧
3. 質問をして、乗っている路線をユーザーに聞いてもよい

## 2. 原因（Claude Codeの調査）
**事実**
- 位置は `navigator.geolocation.watchPosition`（`maximumAge: 5000`）だけで受け取っていた。
  端末は主に「動いたとき」に位置を知らせるため、停車中や画面を開き直した直後に届かない時間があった
- 「更新: 時刻」は**最後に描画した時刻**で、位置がどれだけ古いかは分からなかった
- 乗車路線は「連続して停車した2駅に共通する路線」で推定していた（`updateRideInference`）。
  1駅目では決まらず、並走区間（新宿〜代々木の山手線と中央・総武線など）では候補が複数残る

**推測**
- 電車内では GPS の精度が落ちやすく、地下区間では位置が届かない。実機での体感はこれより悪い可能性がある

## 3. 実装したこと（`765ced8`）
### 乗車路線
- 停車駅に複数の路線があり判定できないとき、「乗っている路線は？」と全路線のボタンを出す
- ユーザーの選択は自動判定より優先（`rideLineSource = "user"`）
- 選んだ路線が通らない駅に着いたら、乗り換えたとみなして選択を解除し、聞き直す
- 1路線しかない駅に停車したら、その場で確定（2駅待たない）
- 乗り換えシートでも、路線不明なら同じ質問を出す
- 「〇〇に乗車中」のチップを押すと選び直せる。「あとで」はその駅にいる間だけ質問を止める

### 更新タイミング
- 「○秒前に更新」を毎秒表示（`pos.timestamp` 基準）
- 30秒以上届かなければ「位置の更新が止まっています」と赤字で表示し、更新ボタンを強調
- 「今すぐ更新」ボタン（`getCurrentPosition`, `maximumAge: 0`）
- 画面を開き直したとき、5秒以上経っていれば自動で取り直す
- 画面表示中、15秒届かなければアプリ側から取りに行く

## 4. 検証の状況
- **確認済み（Playwright・固定座標）**: 20項目。新宿で質問 → 山手線を選択 → 代々木で維持 → 新宿三丁目で聞き直し →
  代々木八幡で即判定 → 乗り換えシート内の質問 → 停止警告 → 手動更新 → 開き直し → 15秒の自動取得 → 英語表示。JSエラーなし
- **未確認**: 実際の電車内（GPSの届き方、地下区間、停車中の挙動、電池の減り方）
- 注意: テスト用ブラウザは位置が変わったときしか新しい位置を返さないため、手動更新の確認では位置の更新を再現している

## 5. Codexに意見がほしい論点
1. **電池への影響**: 画面表示中に15秒ごとに `getCurrentPosition(enableHighAccuracy: true)` を呼ぶ設計は妥当か。
   車内モードは画面を点けたまま使うので影響が大きい可能性がある。間隔を延ばす・車内モード中は変える、などの案
2. **質問を出すタイミング**: 停車駅で毎回カードが出るのは押しつけがましくないか。
   例: 走行中（駅から離れたとき）だけ出す、乗車中1回だけにする、など
3. **1路線の駅での自動確定**: 今は確定しても表示は「〇〇に乗車中？」（自動判定扱い）。
   1路線なら事実上確実なので「？」を外すべきか
4. **「止まっています」までの30秒**: 地下区間では頻繁に出る可能性がある。地下と分かるときの文言や、しきい値の妥当性
5. **見落とし**: 上記以外に、更新タイミング・路線判定で抜けている観点
