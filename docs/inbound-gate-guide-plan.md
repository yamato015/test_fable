# 外国人向け改札案内機能 実装計画 (v2)

状態: Phase A 実装済み・公開中 (2026-07 オーナー判断でトリガー前倒し)。Phase B/C は未着手

## 市場環境 (2026-07時点の裏付け)
- JR東日本: 2027年春から近距離きっぷをQR乗車券化、磁気きっぷ廃止
- 首都圏8社 (JR東・京成・京急・西武・東武など) が共通サーバーで会社またぎQR乗車券を導入予定
- 訪日客はすでにQR主流: Skyliner QR eチケット、Klook/KKdayのQRパス、Osaka Metro QRデジタル乗車券
- 示唆: 「IC中心のガイド」は半歩古い。きっぷ種別ごとの出し分けが本質

## 解決する痛み (優先度順)
1. 自分のきっぷ種別での改札の通り方が分からない (QRはリーダー付き改札機を探す必要がある = 最大の詰みポイント)
2. ICカード (Suica/PASMO/Welcome Suica/モバイルSuica) の買い方・チャージ・タッチ
3. 残高不足時の精算機 (Fare Adjustment)
4. 会社をまたぐ乗換 (JR⇔メトロは別料金・乗換改札)
5. JR Passは自動改札不可 → 有人改札へ

## コア設計: きっぷプロフィール (個別最適化)
初回に1問「What are you traveling with?」
- 📱 QR ticket → QRリーダー付き改札の見分け方 / かざす位置 / 画面輝度の注意
- 💳 IC card / Mobile Suica → タッチ位置 / 残高 / 精算機
- 🎫 Paper ticket → 挿入して取る / 2027年QR移行の注意
- 🚅 JR Pass → 有人改札へ
選択を localStorage に保存し、以降のガイド・現在駅連動の注意をその種別に合わせて出し分け。
完全オフライン・外部送信ゼロ (エキココの原則のまま)。

## 実装トリガー (どちらかで着手)
- Tally機能投票で「外国人向け乗り方ガイド」が1位
- 英語モード利用率10%超 or 海外からの訪問が明確

## Phase A: きっぷプロフィール + 静的ガイド (MVP・実装1〜2日)
- ENモード時に「🎫 Station Guide」→ 種別選択 → 種別別ガイド
- 既存i18n基盤 (data-i18n) に乗せる。オフライン・追加容量ほぼゼロ・外部依存ゼロ
- 図解は絵文字+自作SVG (著作権リスクなし)

## Phase B: 文脈連動 (1〜2日)
- 路線名プレフィックスから事業者判定 (JR/東京メトロ/都営/私鉄)
- 現在駅×きっぷ種別の注意 (例: QR選択者がJR駅→「QRリーダーのある改札へ」)
- 乗車路線の推定が事業者をまたいだら「別会社=運賃が別」警告

## Phase C: 本格インバウンド (投資判断後)
- 中国語(簡体)・韓国語 (STRINGS追加のみ)
- 収益二本柱:
  1. 7日間パス買い切り (例: ¥500・Stripe) — 訪日客にサブスクは不適合
  2. パス購入アフィリエイト (Klook/KKday) — ガイド内に「Tokyo Subway 72h をQRで買う」導線。
     提携交渉不要で始められる。API連携・公式提携はトラクション後の交渉事項
- 出口案内 (OSM出口データの品質検証が前提)
- 配布: Reddit r/JapanTravel 等の英語圏チャネル

## 旅行アプリ連携の段階論
1. 今: なし (計画のみ)
2. Phase C: アフィリエイトリンク (誰でも可・審査のみ)
3. トラクション後: 事業者アプリ・OTAとの公式連携交渉 (チケット種別の自動判定など)

## 成功指標
- ENユーザーのガイド開封率 30%+ / きっぷプロフィール設定率
- アフィリエイト成約数 / 7日パス購入数 (Phase C)

## リスク
- 内容の陳腐化 (QR移行は進行中の変化) → 金額・固有名詞は最小限、「見分け方・仕組み」中心に
- 全改札にQRリーダーが無い過渡期が続く → むしろガイドの価値が上がる期間
- 日本語圏SNSでは訪日客に届かない → チャネルを分ける
