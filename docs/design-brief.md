# エキココ (EkiKoko) — UI/UXデザイン刷新 要件定義書

> このドキュメントは、別のClaude会話（ClaudeDesign）にそのまま貼り付けて
> デザイン案を作ってもらうためのものです。返ってきた案は、この文書の
> 「デザイン受け渡しフォーマット」に沿っていれば、この開発者(Claude Code)側で
> 既存コードにそのまま統合できます。

---

## 1. プロダクト概要

**エキココ**は、電車内で「いま自分がどの駅にいるか」を特大表示で確認できるPWA。
混雑した車内で座っていると電光掲示板が見えない——という日常の小さな不便を
解決するのが唯一の目的。乗換案内アプリではない（経路検索・時刻表は非対応）。

- 一人開発・PoC段階・現在β公開直前
- フレームワーク不使用のバニラJS/HTML/CSS、ビルド工程なし
- GitHub Pagesで静的配信、固定費ゼロ

## 2. 使われ方（デザインに直結する制約）

- **利用シーン**: 満員電車・座席・片手・チラ見。両手が塞がっていることもある
- **視認性が最優先**: 座った姿勢から一瞥で駅名がわかる必要がある（現状、駅名は
  `clamp(2.4rem, 13vw, 4rem)` の特大表示。この設計思想は死守）
- **車内モード**: 画面をずっと点灯させ膝の上や手元に置く用途があるため、
  **OLEDでの消費電力を抑える真っ黒背景**が要件（現状 `#000` 固定）
- **ターゲット**: 日本の通勤・通学者がメイン。副次的に訪日外国人（多言語対応あり）

## 3. 今回のゴール

**見た目・世界観の完成度を一段引き上げること**（情報設計・画面構成・機能配置は
今回の主眼ではない — 大きく変えなくてよい）。

現状は「動くけど素朴なダークUI」の域を出ていない、というのが自己評価。
GitHub風の配色（`#0d1117`背景・`#3fb950`アクセント）を素朴に使っているだけで、
プロダクトとしての作り込み感・ブランドの個性が弱い。

**期待する変化のイメージ**（いずれも一例、縛りではない）:
- 単なる「ダークモードのカード羅列」から抜け出した、記憶に残るビジュアル言語
- 「駅」「電車」「移動」を想起させるモチーフ・タイポグラフィ・余白設計
- 特大駅名表示が単に大きいだけでなく、"魅せる"演出になっている
- ボタン・カード・バッジなどコンポーネントの質感（フラットすぎない、かといって
  過剰な装飾でもない）
- ライトモード対応も検討する場合はぜひ（現状ダーク固定＋アクセント3色切替のみ）

## 4. 現在のデザイントークン（`style.css` より抜粋）

```css
:root {
  --bg: #0d1117;
  --fg: #e6edf3;
  --sub: #8b949e;
  --accent: #3fb950;
  --accent2: #58a6ff;
  --card: #161b22;
  --danger: #f85149;
}
/* テーマ切り替え(🎨ボタンで3色をユーザーが選べる) */
body[data-theme="blue"] { --accent: #58a6ff; --accent2: #3fb950; }
body[data-theme="pink"] { --accent: #f778ba; --accent2: #58a6ff; }
```

- フォント: `"Hiragino Sans", "Noto Sans JP", "Yu Gothic", sans-serif`（Webフォント
  不使用＝追加読み込みなしを維持したい。変更するならシステムフォントの範囲で）
- 角丸多用（`border-radius: 12px〜999px`）、影はほぼ未使用
- 単一の `style.css`（783行）で全画面を管理。CSSフレームワーク不使用

## 5. 画面インベントリ

| 画面 | 役割 | 現状の見た目の課題（仮説） |
|---|---|---|
| 起動画面 (`#start-screen`) | ロゴ＋タグライン＋CTAボタン1つ、中央揃え | 背景が単色で間延び。第一印象を決める最重要画面なのに作り込みが薄い |
| メイン画面 (`#main-screen`) | 駅名特大表示（カード）＋周辺駅リスト＋モードボタン群 | ボタンが縦に3つ並ぶだけ。カードの階層・余白にメリハりがない |
| 車内モード (`#riding-screen`) | 全画面・真っ黒・駅名超特大 | 情報は正しいが無機質。"魅せる"要素があってよい |
| 目的地ピッカー/路線図モーダル | 検索・タブ切替・路線図（縦ライン+丸） | 機能優先の実装で装飾ゼロ。路線図はもっと"路線図らしく"できる余地 |
| 乗り方ガイドモーダル (`#guide-modal`) | きっぷ種別チップ→該当ガイド表示 | 新機能。テキスト中心で単調 |
| プレミアム(paywall)モーダル | 機能リスト＋価格＋CTA | コンバージョンに直結する画面なのに簡素 |
| 降車アラート発火画面 (`#alert-overlay`) | 全画面フラッシュ＋駅名 | インパクトはあるが安っぽく見える可能性 |

各画面のスクリーンショットは別途この会話に添付します（あれば貼ってください。
無ければコードの構造から推測して進めて構いません）。

## 6. 変えてよいもの / 変えてはいけないもの

**自由に変えてよい**
- 配色・トーン&マナー全般（3テーマ切替の仕組み自体は維持、色の中身は再設計可）
- タイポグラフィのウェイト・サイズ比率・余白・角丸・影・グラデーション等の装飾
- アイコン・イラスト・ロゴのモチーフ（現状ロゴは「エキココ」のテキストのみ）
- マイクロインタラクション（アニメーション・トランジション）
- ライトモードの新設

**変えてはいけない（機能要件）**
- 画面構成・情報の出し分けロジック自体（例: 駅名表示→周辺駅リスト→モードボタン、
  という縦の流れは維持。並び替え・大枠のレイアウト変更は別スコープ）
- 車内モードの**真っ黒背景**（OLED省電力のため。装飾は加えてよいが背景は黒基調）
- 駅名の**特大サイズ・視認性**（座った姿勢からのチラ見が最優先事項）
- 各要素の `id`（JSがこれらを直接参照している。デザイン案の時点ではCSSクラス名の
  変更は自由だが、`id`は保持するか、変更する場合は対応表を明記してほしい）

## 7. ブランド言語ヒント

- 名前の由来: 「駅」＋「ここ」＝ 今いる場所がすぐわかる、という直球の安心感
- トーンは「鉄道会社の硬い案内」ではなく、「個人開発者が作った気の利いた小道具」
- 競合（乗換案内アプリ群）と同じ土俵に見えないことが重要。エキココは
  情報過多な地図・時刻表アプリではなく、**単機能に特化した潔さ**が売り
- 絵文字は現状多用（🚉🎯🔔等）。今後アイコン化するなら絵文字依存から
  卒業してもよい

## 8. デザイン受け渡しフォーマット（重要）

ここに書かれた形式で返してもらえれば、そのままこちら側のコードに統合できます。

1. **デザイン方針の要約**（狙った世界観・参照した気分/モチーフを2〜3文）
2. **更新後の `:root` トークン**（CSSカスタムプロパティの形で。3テーマ分の
   `--accent`/`--accent2` 差し替え案も含む）
3. **主要コンポーネントのHTML/CSSスニペット**（以下を優先的に）
   - 起動画面のロゴ・タグライン・CTAボタン
   - メイン画面の駅名表示カード（`.station-display` 相当）
   - ボタン群（`.big-btn` / `.mode-btn` / `.pill-btn` 等 プライマリ/セカンダリ）
   - モーダルの基本シェル（`.modal` 相当）
   - 車内モードの駅名表示（`.riding` 相当・背景は黒のまま）
4. 既存の `id` を変更する場合は **旧→新の対応表**を明記
5. 新しいアイコン/ロゴを提案する場合は、SVGコードまたは十分に再現可能な仕様
   （形状・カラー・比率）で

テキストのみのClaude会話でも、CSS/HTMLコードとして上記を返してもらえれば
十分です。画像生成やFigmaは不要です。
