# 決定ログ

オーナー（ttx）が決めたことを、新しいものが上になるように記録する。
AIは、決定事項と矛盾する作業をする前に、ここを確認すること。

書き方:

```
## YYYY-MM-DD 決定の見出し
- 決定: 何を決めたか
- 理由: なぜそう決めたか
- 関わったAI: 例) Claudeで議論 → ChatGPTでレビュー
```

## 2026-10-26 模倣対策の基本整備を済ませて公開ベータを広める
- 依頼: 「それだけ済ませて世に打ち出したい」を受け、名前の一次調査、独自著作物の利用条件・外部データの出典、企画資料の公開範囲を整える。
- 方針: 通常のアプリ利用・リンク・紹介を妨げず、独自コード等の包括的な再配布・転用許諾をしていないことを明記する。第三者のライセンス・法令上認められる利用を制限しない。
- 資料: 収益計画等7件は非公開管理先と原文控えに保存してから現在の本番から取り下げる。今後の企画資料は公開リポジトリの外で管理する。
- 限界: 商標出願・登録や非侵害保証は含まない。過去の公開履歴・他ブランチ・コピーは残る。SNS投稿は別途未実施。
- 詳細: `docs/releases/2026-10-26-rights-and-public-scope.md`

## 2026-10-26 鉄道会社との連携を公開ベータの前提にしない
- 依頼: オーナーの「鉄道会社とのコラボで満足度が上がる条件はあるか。なければアプリやWebサービスとして一旦ローンチしたい」を受け、連携の価値と現在の公開条件を確認する
- 判断: 地下での乗車列車特定、構内・出口情報、混雑や運行情報には連携の価値がある。一方、現在のGPSによる最寄り駅表示・車内モード・ガイドの公開に、提携を待つ理由は見当たらない
- 進め方: 現在のWeb/PWAを無料の公開ベータとして利用してもらい、実地の感想を集める。提携・データ追加・ストア配信・実課金を今回の待ち条件にしない
- 公開前の調整: 回答欄がないTallyの代わりに、既存の問い合わせ先へメールで感想を送れる導線を使う。公開ページの課金説明を無料・Plusデモの現状に合わせる
- 区別: Webでの公開と告知投稿は別。SNS投稿・鉄道会社への連絡・有料契約はまだ行っていない
- 詳細: `docs/releases/2026-10-26-web-launch.md`、`docs/launch.md`

## 2026-10-23 位置更新と路線選択の改善を実装する
- 依頼: オーナーの「ここで実際の変更項目の整理から実行までしよう」を受け、10月19日の共有資料とCodex返信を実装項目に整理する
- 実装範囲: 車内モードの位置の鮮度、本人選択の保護、非同期結果の順序制御、取得失敗時の間隔、質問の抑制と手動入口、推定と本人選択の表示分け
- 保存先: 指定された `claude/ride-line-select`。本番への取り込み・デプロイは今回の作業に含めていない
- 実装上の初期値（Codexによる選定）: 30秒で鮮度の注意表示、自動補完30秒・失敗後30/60/120秒。路線変更候補は精度100m以内・測位から15秒以内・駅から200m以内・速度不明または3m/s以下で、同じ別駅を3回以上かつ10秒以上観測した場合に確認する
- 継続確認: 数値の最終決定と電池への影響は実際の乗車結果を見て判断。自動推定は本人確認済みの扱いにしない
- 関わったAI: Claude Codeの先行実装 → Codexでレビュー・追加実装・検証
- 詳細: [実装記録](improvements/2026-10-23-位置更新と路線選択-実装.md)

## 2026-10-02 「何号車に乗るか」の乗車位置案内は作らない
- 決定: 目的の出口・階段に近い号車を案内する機能は実装しない
- 理由: エキココが価値を発揮するのは乗車後（車内で現在駅が分からない不安の解消）であり、乗車前の判断を助ける機能は乗換案内アプリの領域。加えて、号車位置の網羅的な無料オープンデータが見当たらず、大手アプリは有料の商用データを使っている。号車位置は編成両数やホームドア工事で変わるため、自前で集めると古い情報で迷わせるリスクもある
- 関連: 「降りる駅の出口案内」は降車時の機能のため、この決定の対象外（実装はオーナー承認待ち）
- 関わったAI: Claudeでデータ源を調査・議論
